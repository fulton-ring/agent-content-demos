# Can the public map find the substations large loads are asking BPA to connect to?

Spike for [issue #190](https://github.com/fulton-ring/agent-content-demos/issues/190). The Bonneville Power
Administration publishes its interconnection queue as a workbook, and each large-load request names a point of
interconnection. We take every request that names a substation, find that substation on aerial imagery, and
check whether HIFLD Next and our [us-substations-verified](../us-substations-verified/) dataset have it.

**Short answer: by count, both sources find nearly all of them. By megawatts, the gap is concentrated in a
few new substations, and the biggest asks don't name a substation at all.** HIFLD Next has no point at the
substation for 5.5% of requests but 12.5% of requested MW (14.9% of live MW). Almost all of that is two new
BPA yards near Boardman: Longhorn (3.0 GW live) and Morrow Flat (0.8 GW). us-substations-verified finds Morrow
Flat and misses only Longhorn: 2.5% of requests, 10.3% of MW. Nothing was misplaced by more than 1 km. And 42%
of requests (45% of live MW) name a tap on a transmission line, where a substation would be built, so no map
can show them yet.

## Run it

```bash
./run.sh            # needs uv; downloads ~9 MB into data/ and runs the notebook (about 10 seconds)
./run.sh --chips    # also draws the aerial-imagery chips behind hand_check.csv (data/chips/, not committed)
```

To read the notebook with its output next to each step: `uv run marimo edit substations.py`. `run.sh` writes
`outputs/` (three tables and `run_log.txt`).

## Data (all public, downloaded at run time)

| Input | Source | Version |
|---|---|---|
| Large-load requests | BPA [Interconnection Request Queue workbook](https://www.bpa.gov/energy-and-services/transmission/interconnection), connection type `LL` | dated 2026-11-09 |
| HIFLD Next substations | `us-substations-verified/dataset/us_substations_hifld_only.csv`: 45,779 substations derived from the ends of HIFLD Next Transmission Lines v1.0.0, with HIFLD's names | commit `b48028f` |
| us-substations-verified | `us-substations-verified/dataset/us_substations.parquet`: those plus 25,846 OpenStreetMap substations HIFLD lacks | commit `b48028f` |
| Counties | Census 2024 county gazetteer (centres, for the automatic join) | 2024 |

HIFLD Next has no substations layer, so the HIFLD Next column is the substations derived from its transmission
lines. BPA overwrites the workbook in place; a run on another day reads that day's queue and reports any request
that `poi_reading.csv` doesn't cover yet.

**Two committed files are the answer key**, because they can't be regenerated by code:

- `poi_reading.csv`: our reading of all 463 points of interconnection as a substation (or the first one offered
  in "A or B"), a line tap, a planned substation, or none.
- `hand_check.csv`: each of the 131 named substations, located on Esri World Imagery (`chips.py`): where it
  is, whether it exists, what each source has within 1 km, a confidence and a one-line note.

## What didn't work or was changed

- **Matching by county, as the issue proposed, fails.** The filed county and state are the load's, not the
  substation's: Allston (Oregon) is filed under Columbia County, WA; Big Eddy (Oregon) under Klickitat, WA; one
  request files Modoc County, CA for a point on Canby, Oregon streets; 61 requests have no state. The automatic
  join searches 100 km around the filed county instead.
- **Voltage didn't help.** Most filings give none and derived HIFLD voltages are floors.
- **Six substations couldn't be confirmed.** Both sources put Christmas Valley, Cedarville Junction, Duckabush,
  East Hills, Gold Beach and Cascade Locks where imagery shows no yard (7 requests, 0.05 GW). They are left out
  rather than called misplaced.
- **Ten identifications are low confidence** (marked in `hand_check.csv` with the reason), mostly small utility
  substations whose only point has a placeholder name. Two of them, Canby (Oregon) and Victor (Idaho), are among
  HIFLD's real gaps, together 2 requests and 7 MW; the rest are found or found under another name.

## What this doesn't show

- **Whether the requests get built.** Requested MW are asks; most of a queue never connects.
- **Which requests are data centers.** BPA publishes no end-use field, and we don't label any.
- **Other regions.** BPA's grid is well mapped, and the gap here is new 500 kV yards. PJM or ERCOT may differ.
- **Independence.** Some OSM substations were imported from the old HIFLD layer, so verified and HIFLD agree
  partly by origin. The imagery check is the ground truth here.
- **The joined list.** `hand_check.csv` and `poi_reading.csv` link request numbers to substations, as the issue
  asked for an answer key; this README publishes only counts, shares and the top ten.
